# CSV Event Import Design Tree

Status: Ready for implementation

## Goal

Allow an admin to upload a CSV that creates an event, creates multiple pools, and fills those pools with seeded teams and pool setup details.

## Current App Shape

An event currently has:

- `code`
- `name`
- `pools`
- `activePoolId`
- `updatedAt`

A pool currently has:

- `id`
- `title`
- `division`
- `teamCount`
- `gamesPerMatch`
- `targetScore`
- `pointCap`
- `teams`
- `matches`
- `imagePreview`
- `updatedAt`

The app can already generate match schedules from team count, so the v1 CSV should probably import event, pool, and team data, then let the app generate matches.

## Proposed V1 CSV Shape

One row per team.

```csv
event_code,event_name,pool_key,pool_title,pool_order,division,team_count,games_per_match,target_score,point_cap,schedule_preset,seed,team_name
SUMMER-2026,Summer Cheabs Open,open-a,Open A,1,Open,4,2,15,17,default,1,Team Alpha
SUMMER-2026,Summer Cheabs Open,open-a,Open A,1,Open,4,2,15,17,default,2,Team Beta
SUMMER-2026,Summer Cheabs Open,open-a,Open A,1,Open,4,2,15,17,default,3,Team Gamma
SUMMER-2026,Summer Cheabs Open,open-a,Open A,1,Open,4,2,15,17,default,4,Team Delta
SUMMER-2026,Summer Cheabs Open,open-b,Open B,2,Open,5,2,11,13,default,1,Team Echo
```

## Column Contract

| Column | Required | Notes |
| --- | --- | --- |
| `event_code` | Yes | Admin supplied event code. Import creates a new event only. |
| `event_name` | Yes | Display name for the event. |
| `pool_key` | Yes | Stable CSV import grouping key, not the generated app pool ID. Internal only after import. Example: `open-a`. |
| `pool_title` | Yes | Display name for the pool. |
| `pool_order` | No | Numeric display order. If omitted, order is inferred from first appearance of each `pool_key` in the file. |
| `division` | Yes | Must match one of `Open`, `AA`, `A/AA`, `A`, `BB`, `B/BB`, `B`. |
| `team_count` | Yes | Current supported values appear to be `3`, `4`, `5`, `6`, `7`. |
| `games_per_match` | No | Defaults to `2` if blank. |
| `target_score` | No | Defaults from current app rules if blank. |
| `point_cap` | No | Blank means no cap. Nonblank values must be whole numbers greater than or equal to `target_score`. |
| `schedule_preset` | No | `default` means generate from team count. |
| `seed` | Yes | Must be unique within a pool and should cover `1..team_count`. |
| `team_name` | Yes | Display name for the team. |

## Decision Tree

### 1. Import Target

Question: Does CSV upload only create a brand-new event, or can it modify an existing event?

- Option A: Create new event only.
- Option B: Replace an existing event with the same `event_code`.
- Option C: Append pools to an existing event.
- Option D: Merge by `pool_key`.

Decision: Only create a brand new event

### 2. Event Code

Question: Is `event_code` supplied by the CSV, generated by the app, or either?

- Option A: CSV must provide it.
- Option B: App always generates it.
- Option C: CSV may provide it; app generates if blank.

Decision: Supplied by the CSV

### 3. Pool Completeness

Question: Must every pool be completely filled at import time?

- Option A: Require exactly `team_count` teams.
- Option B: Allow partial pools and create placeholder teams.
- Option C: Allow partial pools but do not create the event until admin confirms.

Decision: Yes, require exactly team_count for pools

### 4. Existing Scoring Data

Question: Can an import touch an event or pool after scoring has started?

- Option A: No.
- Option B: Only append brand-new pools.
- Option C: Allow edits if no scored match in that specific pool.
- Option D: Allow full overwrite with explicit confirmation.

Decision: No

### 5. Team Data

Question: Is `team_name` enough, or do we need more columns now?

Possible extra columns:

- `player_1`
- `player_2`
- `club`
- `city`
- `state`
- `email`
- `phone`
- `registration_id`
- `rank`
- `notes`

Decision: Just `team_name`

### 6. Division Validation

Question: Should imports be limited to known division names?

- Option A: Strictly validate against existing division options.
- Option B: Allow arbitrary division names.
- Option C: Warn on unknown divisions but allow import.

Decision: Strict Validation

### 7. Scoring Rules

Question: Can scoring rules vary by pool, or should they be event/division defaults?

- Option A: Rules are per pool, as the current data model allows.
- Option B: Rules are per division, with each pool inheriting them.
- Option C: Rules are event-wide.

Decision: Per Pool

### 8. Match Schedule

Question: Does v1 need custom match rows/ref assignments in CSV?

- Option A: No, generate from `team_count`.
- Option B: Yes, same CSV includes match columns.
- Option C: Yes, separate optional match CSV.

Decision: Option A

### 9. Error Handling

Question: What should the admin see before the event is created?

- Option A: Dry-run preview with all blocking errors and warnings.
- Option B: First error only.
- Option C: Create what is valid and report skipped rows.

Decision: Option A

### 10. Duplicate Handling

Question: What counts as a duplicate?

Potential duplicate checks:

- Duplicate `pool_key`.
- Duplicate `pool_title`.
- Duplicate `seed` within a pool.
- Duplicate `team_name` within a pool.
- Duplicate `team_name` across event.

Decision: Go with `Current Leaning`

### 11. Event Code Normalization

Question: Should `event_code` be case-normalized to uppercase on import, or should lowercase codes be rejected?

Decision: Normalize to uppercase, matching the existing codebase behavior.

### 12. Pool Key Visibility

Question: Should `pool_key` be visible to admins after import, or is it only an internal CSV grouping key?

Decision: Internal only.

### 13. Conflicting Pool Settings

Question: If two rows for the same `pool_key` disagree on `pool_title`, `division`, or scoring settings, should that be a blocking error even if one value is blank?

Decision: Yes. Any conflicting pool-level setting for the same `pool_key` is a blocking error.

### 14. Games Per Match Scope

Question: Should `games_per_match` be allowed to vary per pool, or should it be constrained globally per event?

Decision: Varies per pool.

### 15. No-Cap Score Input Limit

Question: For no-cap pools, should score inputs still have a max like `99`, or should the UI allow any practical score?

Decision: Still use a practical UI maximum.

### 16. Pool Order

Question: Should the CSV require `pool_order`, or should omitted order be inferred from first appearance in the file?

Decision: Infer omitted pool order from first appearance in the file.

### 17. Pool Title Uniqueness

Question: Should pool titles have to be unique across the event, or can two divisions both have `Pool A`?

Decision: Pool titles do not have to be unique across the event.

### 18. Team Name Duplicate Normalization

Question: Should `team_name` be trimmed and collapsed for duplicate detection, such as treating `Team  Alpha` and `Team Alpha` as the same warning?

Decision: Yes. Trim and collapse whitespace for duplicate detection.

### 19. Unknown Extra Columns

Question: Should unknown extra CSV columns be ignored, warned about, or blocked?

Decision: Warn, but do not block.

### 20. Preview Detail

Question: Should the import preview show the generated match schedule before confirmation, or just pool/team summaries?

Decision: Show the generated match schedule as well.

### 21. Backend Write Shape

Question: Should the importer create the event and all pools through one new backend endpoint, or reuse the current create-event endpoint followed by one pool-save request per pool?

Decision: Use one new atomic backend import endpoint. The event and all pools should either be created together or not created at all.

### 22. Validation Location

Question: Should CSV parsing happen entirely in the browser, entirely on the server, or browser preview plus server-side validation before commit?

Decision: Browser parsing for immediate preview, plus server-side validation before commit. The server remains authoritative.

### 23. Confirmation Checkbox

Question: Should the preview require an explicit checkbox such as "I reviewed these pools" before enabling import?

Decision: No explicit checkbox.

### 24. Post-Import Navigation

Question: After successful import, should the admin land on the event dashboard or the first imported pool?

Decision: Event dashboard.

### 25. CSV Template

Question: Should the app offer a downloadable CSV template from the import page?

Decision: Yes.

### 26. Template Content

Question: Should the template include only headers, or headers plus example rows?

Decision: Headers only.

### 27. Upload Control

Question: Should the import page allow drag-and-drop, file picker only, or both?

Decision: File picker only.

### 28. Validation Message References

Question: Should validation messages cite CSV row numbers using the original file line number, grouped pool/team context, or both?

Decision: Use original file line numbers.

### 29. Warning Behavior

Question: Should warnings block the primary import button visually until dismissed, or should warnings simply remain visible while import is allowed?

Decision: Warnings remain visible while import is allowed.

### 30. Preview Order

Question: Should the preview sort pools by inferred/imported `pool_order`, or preserve raw file order exactly?

Decision: Preserve raw file order in preview.

### 31. Import Size Limits

Question: Should there be a maximum CSV file size or maximum number of rows for v1?

Decision: No explicit v1 limit.

### 32. Accepted File Type

Question: Should the importer accept only `.csv` files by extension, or also accept any text file with CSV content?

Decision: Accept only `.csv` files.

### 33. Server Rejection UX

Question: If the server rejects the import after the browser preview passed, should the UI keep the parsed preview visible and show server errors inline?

Decision: Yes. Keep the parsed preview visible and show server errors inline.

### 34. Retry Behavior

Question: Should import failures be retryable from the same selected file without reselecting it?

Decision: No. Admin should reselect the file before retrying.

### 35. Route Protection

Question: Should this feature be behind an admin-only route guard, or is the choose-event page already sufficiently protected for import controls?

Decision: Use an admin-only route guard.

### 36. Header Case

Question: Should header names be case-sensitive, or should `Event_Code` and `event_code` both work?

Decision: Header matching is case-insensitive.

### 37. UTF-8 BOM

Question: Should the importer accept UTF-8 BOM files from Excel without warning?

Decision: Accept UTF-8 BOM files, but warn.

### 38. Blank Lines

Question: Should completely blank lines be ignored or treated as errors?

Decision: Treat blank lines as errors.

### 39. Trailing Empty Column

Question: Should a trailing comma / empty extra final column warn as an unknown column?

Decision: No. Do not warn for a trailing empty final column.

### 40. Template Header Style

Question: Should exported template columns use snake_case exactly as proposed, or friendlier names with spaces?

Decision: Use the proposed `snake_case` headers.

### 41. Import Route

Question: Should the import route be `/import-event`, `/events/import`, or another path?

Decision: Use `/import-event`.

### 42. Primary Action Label

Question: What should the primary action button say: `Import Event`, `Create Event`, or something else?

Decision: `Import Event`.

### 43. Template Download Filename

Question: Should the template download filename be fixed, such as `cheabs-event-import-template.csv`?

Decision: Do not require a fixed filename.

### 44. Initial Active Pool

Question: Should the generated event's `activePoolId` be the first pool in raw file order?

Decision: Yes. Use the first pool in raw file order.

### 45. Spec Readiness

Question: Should we keep this markdown as the implementation spec and mark it ready after these answers?

Decision: Yes. This markdown is the implementation spec.

## Validation Rules

Draft blocking errors:

- Selected file does not use a `.csv` extension.
- Missing required headers.
- Empty required values.
- Completely blank lines.
- More than one `event_name`.
- Missing `event_code`.
- More than one `event_code`.
- Existing event with the same normalized `event_code`.
- Unknown `division`.
- Unsupported `team_count`.
- Non-numeric `seed`, `team_count`, `games_per_match`, `target_score`, `point_cap`, or `pool_order`.
- Nonblank `point_cap` less than `target_score`.
- Duplicate `seed` within a `pool_key`.
- Missing seed in range `1..team_count`.
- More teams than `team_count`.
- Fewer teams than `team_count`.
- Conflicting pool settings across rows with the same `pool_key`.

Draft warnings:

- Duplicate `team_name`.
- Blank optional values that will use defaults.
- Blank `point_cap`, because that means no cap.
- Unknown extra CSV columns.
- Duplicate normalized `team_name`.
- UTF-8 BOM detected.

## Open Questions

1. Do admins know final pool assignments before import? yes
2. Should the importer support editing existing events in v1? no
3. Do we need player-level fields now? no
4. Are custom match schedules real requirements or future flexibility? future flexibility
5. Should blank `point_cap` mean default cap, or no cap? no cap
6. Should CSV import be available only from the choose-event page, or also from inside an event? only from choose-event page

## Implementation Notes

Potential flow:

1. Admin opens import screen.
2. Admin can download a headers-only CSV template.
3. Admin chooses a `.csv` file through a file picker.
4. App parses locally and shows preview in raw file order.
5. Preview groups rows by event and pool.
6. App shows blocking errors, warnings, computed defaults, and generated match schedules.
7. Admin confirms if there are no blocking errors.
8. App submits the parsed import payload to one backend endpoint.
9. Server validates again and atomically creates the event and all pools.
10. If the server rejects the import, the app keeps the preview visible and shows server errors inline.
11. Server sets `activePoolId` to the first pool in raw file order.
12. On success, app navigates to the event dashboard.

Potential parser behavior:

- Match header names case-insensitively.
- Trim surrounding whitespace.
- Collapse internal whitespace for duplicate detection.
- Preserve internal whitespace in names.
- Support quoted CSV fields.
- Accept UTF-8 BOM files, but produce a warning.
- Ignore a trailing comma / empty extra final column for unknown-column warnings.
- Treat empty optional cells as defaults, except `point_cap`, where empty means no cap.
- Treat empty required cells as errors.

## Implementation Surface

- Route: `/import-event`
- Primary action: `Import Event`
- Template download: headers-only CSV, no fixed filename requirement.
- Route protection: admin-only route guard.
- Successful import destination: event dashboard.
